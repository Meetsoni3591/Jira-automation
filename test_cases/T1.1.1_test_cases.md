# Test Cases for T1.1.1 - Enable product management for admins

Okay, here are two detailed test cases derived from the provided task "Enable product management for admins" and the description "Support secure user registration, login, and checkout process."  These test cases focus on different aspects of the task and prioritize potential areas of concern.

**Test Case 1: Admin User Registration and Login Security**

*   **Title:** Verify Secure Admin User Registration and Login with Strong Password Policy
*   **Description:** This test case verifies that the registration process for admin users adheres to security best practices, including a strong password policy, prevention of common vulnerabilities like SQL injection, and proper handling of sensitive data during registration and login.
*   **Steps:**

    1.  **Navigate to the Admin User Registration Page:** Access the admin registration page (e.g., `/admin/register`).
    2.  **Attempt Registration with Weak Password:** Enter a username (e.g., "testadmin"), email address (e.g., "testadmin@example.com"), and a weak password (e.g., "password", "123456", or a password easily found in password dictionaries).
    3.  **Submit Registration Form.**
    4.  **Attempt Registration with Special Characters in Username/Email:** Enter username or email address with special characters such as single quotes(') or double quotes(") and then submit the registration form.
    5.  **Enter valid username, valid email address, and valid password and submit the registration form.**
    6.  **Navigate to the Admin Login Page:** Access the admin login page (e.g., `/admin/login`).
    7.  **Attempt Login with Incorrect Credentials:** Enter the registered username and a deliberately incorrect password.
    8.  **Attempt Login with Valid Credentials:** Enter the registered username and the correct password.
    9.  **After successful login, attempt logout.**

*   **Expected Result:**

    1.  The system should reject the weak password with a clear and informative error message, specifying the minimum password strength requirements (e.g., minimum length, required character types).
    2.  The system should reject the invalid characters in username and email address, and display an error message.
    3.  The admin user should be registered successfully and an email should be sent to verify the email address (if configured).
    4.  The system should display an error message indicating invalid login credentials. This message should not reveal whether the username exists or not to prevent account enumeration.
    5.  The admin user should be successfully logged into the admin panel.
    6.  The admin user should be successfully logged out of the admin panel.

*   **Priority:** High - Security of admin accounts is critical to the overall system security.

**Test Case 2: Admin Initiated Checkout Process Validation**

*   **Title:** Verify Secure Admin Initiated Checkout Process Functionality and Data Integrity
*   **Description:** This test case verifies that an admin can initiate a checkout process for a user (e.g., creating orders on their behalf), ensuring that the process is secure, accurate, and that all relevant data is properly handled and stored.
*   **Steps:**

    1.  **Login as Admin:** Log in to the admin panel with valid admin credentials.
    2.  **Navigate to User Management:** Navigate to the section of the admin panel where user accounts are managed.
    3.  **Select a User:** Select an existing user for whom to initiate a checkout.
    4.  **Initiate Checkout Process:** Locate the "Initiate Checkout" or similar functionality associated with the user.
    5.  **Add Products to Cart:** Using the admin interface, add products to the user's cart. Note the product names, quantities, and prices. Try adding products with special characters (like ' " ) in the name to test sanitization.
    6.  **Apply Discounts/Coupons (if applicable):** Apply any available discounts or coupons to the cart. Note the discount amount.
    7.  **Select Shipping Address:** Select a shipping address for the order. This could be an existing address for the user or the ability to add a new one.
    8.  **Select Payment Method:** Select a payment method for the order. *Important: For security, **DO NOT** enter actual credit card details in a live system during testing. Use test payment gateway credentials or a bypass mechanism configured for testing purposes.*
    9.  **Review Order Summary:** Carefully review the order summary, including product details, quantities, prices, discounts, shipping address, and total amount.
    10. **Confirm Checkout:** Confirm the checkout process.
    11. **Verify Order Confirmation:** Check for an order confirmation message or page.
    12. **Verify User's Order History:** Log in as the user and verify that the order is correctly displayed in their order history.
    13. **Verify Order Details in Admin Panel:** Log back in as admin and verify the order details in the admin panel, ensuring they match the user's order history and the initial input during checkout.
    14. **Attempt to Modify the completed order.**

*   **Expected Result:**

    1.  Admin user successfully logs into the admin panel.
    2.  Admin user successfully navigates to the user management section.
    3.  Admin user is able to select a user account.
    4.  Admin user is able to initiate the checkout process for the selected user.
    5.  Products are added to the cart correctly, with the correct quantities and prices. Product names with special characters are handled correctly (ideally sanitized to prevent display issues).
    6.  Discounts/coupons are applied correctly, and the total amount is accurately calculated.
    7.  Shipping address is selected or added successfully.
    8.  Payment method is selected successfully (using test credentials/bypass).
    9.  The order summary displays all the correct information.
    10. The order is successfully placed, and an order confirmation is generated.
    11. The order appears correctly in the user's order history, with all the correct details.
    12. The order details in the admin panel match the user's order history and the checkout input, including product details, quantities, prices, discounts, shipping address, and total amount.
    13. No unauthorised modifications should be allowed after the order is placed, or all changes should be logged.

*   **Priority:** High -  Ensuring a secure and correct checkout process is vital for both user trust and revenue generation. Incorrect data handling or security vulnerabilities could have serious consequences.
