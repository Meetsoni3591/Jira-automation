**Test Case 1: Data Migration from MySQL to PostgreSQL - Numeric Data Type Verification**

*   **Title:** Data Migration - MySQL to PostgreSQL - Numeric Integrity Check
*   **Description:** This test case verifies the integrity of numeric data when migrating data from a MySQL database to a PostgreSQL database. It specifically focuses on ensuring that numeric data types (INT, DECIMAL, FLOAT) are accurately converted and stored in PostgreSQL without any loss of precision or data corruption. This test is critical to ensure data consistency and accuracy after migration.
*   **Steps:**

    1.  **Setup Environment:**
        *   Ensure that both MySQL and PostgreSQL servers are running and accessible.
        *   Create a source database named `mysql_source` in MySQL.
        *   Create a destination database named `postgresql_destination` in PostgreSQL.
        *   Install and configure a data migration tool (e.g., `pgloader`, `AWS DMS`, custom script). For this example, we'll assume using a script that can directly read from one database and write to another.
    2.  **Populate MySQL Data:**
        *   In the `mysql_source` database, create a table named `numeric_data`:
            ```sql
            CREATE TABLE numeric_data (
                id INT PRIMARY KEY AUTO_INCREMENT,
                int_value INT,
                decimal_value DECIMAL(10, 2),
                float_value FLOAT
            );
            ```
        *   Insert a variety of numeric values into the `numeric_data` table, including:
            *   Positive and negative integers.
            *   Decimal values with varying precision and scale.
            *   Floating-point values, including very small and very large numbers, as well as special values like NaN (Not a Number) and Infinity (if supported by MySQL's configuration).
            *   Boundary values (minimum and maximum values for each data type).
            Example:
            ```sql
            INSERT INTO numeric_data (int_value, decimal_value, float_value) VALUES
            (12345, 1234.56, 123.456),
            (-67890, -678.90, -67.890),
            (2147483647, 99999999.99, 3.40282e+38), --Max INT, Max DECIMAL, Max FLOAT
            (-2147483648, -99999999.99, -3.40282e+38), --Min INT, Min DECIMAL, Min FLOAT
            (0, 0.00, 0.00);
            ```
    3.  **Configure Data Migration:**
        *   Configure the data migration tool to connect to both `mysql_source` and `postgresql_destination`.
        *   Configure the tool to migrate the `numeric_data` table from MySQL to PostgreSQL.
        *   Verify that data type mappings are correctly configured (e.g., MySQL INT to PostgreSQL INTEGER, MySQL DECIMAL to PostgreSQL NUMERIC, MySQL FLOAT to PostgreSQL REAL or DOUBLE PRECISION depending on desired precision).  *This is a critical step to prevent implicit truncation!*
    4.  **Execute Data Migration:**
        *   Run the data migration process.
        *   Monitor the migration process for any errors or warnings.
    5.  **Verify Data in PostgreSQL:**
        *   In the `postgresql_destination` database, create a table named `numeric_data` with the exact same structure as the `numeric_data` table in MySQL (using appropriate PostgreSQL data types).
        *   After the data migration is completed, execute a query in PostgreSQL to retrieve all data from the `numeric_data` table:
        ```sql
        SELECT * FROM numeric_data;
        ```
        *   Compare the data in the PostgreSQL table with the original data in the MySQL table.  Verify that all numeric values are accurately transferred and that there is no data loss or corruption.
    6.  **Data Validation Check:**
        *   Write a SQL script in both databases to check the following:
        *   `COUNT(*)` result in both databases match
        *   Hash checksums of specific columns match by fetching the same data in both databases and using some function (e.g. SHA256 or MD5) to calculate the column values and match them up. This ensures the integrity of the data in a programmatic way.

*   **Expected Result:**

    *   The data migration process completes without errors.
    *   A table named `numeric_data` is created in the `postgresql_destination` database.
    *   All data from the `numeric_data` table in the `mysql_source` database is successfully migrated to the `numeric_data` table in the `postgresql_destination` database.
    *   All numeric values in the PostgreSQL table are identical to the corresponding values in the MySQL table, including positive/negative signs, decimal places, and special values.  No data is truncated or corrupted.
    *   Data validation checks in both databases pass.

*   **Priority:** High

**Test Case 2: Document Structure Validation after Migration from MongoDB**

*   **Title:** MongoDB Data Export and Import Structure Validation
*   **Description:** This test case aims to validate the integrity of document structures when migrating data out of MongoDB using JSON format, and importing it back.
*   **Steps:**
    1. **Setup Environment:**
        *   Ensure that a MongoDB server is running and accessible.
        *   Create a database named `mongo_source`.
        *   Create a collection named `users` in the `mongo_source` database.
    2.  **Populate MongoDB Data:**
        *   Insert sample JSON documents into the `users` collection. These documents should include a variety of data types, including:
            *   Strings
            *   Numbers (integers, decimals, doubles)
            *   Booleans
            *   Arrays (of strings, numbers, and other documents)
            *   Embedded documents (nested JSON objects)
            *   Dates
            *   Null values
            *   Objects with different data types to be saved to the data base.

        ```javascript
        db.users.insertMany([
        {

            "age": 30,

            "address": {

                "city": "Anytown",
                "zip": "12345"

            "hobbies": ["reading", "hiking", "coding"],
            "is_active": true,

                "bio": "Software engineer",

        {

            "name": "Jane Smith",

            "profile": {
                "bio": "Graphic designer",
                "skills": ["Photoshop", "Illustrator", "InDesign"]
            }
        }
        ])
        ```
    3.  **Export Data from MongoDB:**
        *   Use the `mongoexport` utility or a similar tool to export the `users` collection from the `mongo_source` database to a JSON file (e.g., `users.json`).  Use the `--jsonArray` parameter to ensure the exported data is in a JSON array format if that's how you intend to re-import it.
        *   Store the timestamp before exporting the data in a variable.
        ```bash
        mongoexport --db mongo_source --collection users --out users.json --jsonArray
        ```
    4.  **Verify JSON Format:**
        *   Open the exported JSON file in a text editor or using a JSON validator to ensure it is well-formed and contains the expected data.
    5.  **Import Data Back into MongoDB:**
        *   Create a new database in MongoDB named `mongo_destination`.
        *   Use the `mongoimport` utility or a similar tool to import the data from the JSON file into a new collection named `users_imported` in the `mongo_destination` database.
        ```bash
        mongoimport --db mongo_destination --collection users_imported --file users.json --jsonArray
        ```
    6.  **Validate Data Structure:**
        *   Connect to the `mongo_destination` database using the MongoDB shell or a similar client.
        *   Run queries to retrieve documents from the `users_imported` collection and compare them to the original documents in the `users` collection in `mongo_source`.
        *   Specifically, verify the following:
            *   The number of documents in both collections is the same.
            *   All fields and their corresponding data types are present and correct in the imported documents.
            *   Embedded documents and arrays are correctly nested and contain the expected data.
            *   Dates are correctly imported and represented as ISODate objects.
            *   Null values are correctly preserved.
            *   Field orders are not explicitly verified (MongoDB does not guarantee field order).
    7.  **Validate Data Content:**
        *   Write a javascript script in both databases to check the following:
        *   `COUNT(*)` result in both databases match
        *   Each column value match in both databases for the specific columns using a programmatic check like fetching values and running `assert` function.

*   **Expected Result:**

    *   The `mongoexport` command executes without errors, and a valid JSON file is created.
    *   The `mongoimport` command executes without errors, and a new collection named `users_imported` is created in the `mongo_destination` database.
    *   The `users_imported` collection contains the same number of documents as the `users` collection in `mongo_source`.
    *   All documents in the `users_imported` collection have the same structure and data types as the corresponding documents in the `users` collection.
    *   Embedded documents and arrays are correctly nested and contain the expected data.
    *   Dates are correctly imported as ISODate objects.
    *   Null values are correctly preserved.
    *   Data content checks in both databases pass.

*   **Priority:** High
