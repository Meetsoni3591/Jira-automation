# Test Cases for T1.4.1 - Frontend

Okay, here are two detailed test cases based on the provided task, designed from the perspective of a senior QA engineer:

**Test Case 1:  Responsive Layout Functionality Across Different Screen Sizes**

*   **Title:** Responsive Layout Adaptation on Various Screen Sizes
*   **Description:** Verifies that the website layout and content adapt appropriately and remain visually appealing across a range of common screen resolutions and device types (desktop, tablet, mobile).  This test case covers key elements of responsive design implementation.
*   **Steps:**

    1.  **Setup:** Open the website in a supported browser (Chrome, Firefox, Safari, Edge).
    2.  **Initial State:** Maximize the browser window on a desktop computer.
    3.  **Screen Size Reduction (Desktop):** Gradually reduce the browser window width, observing the layout changes at various breakpoints. Specifically note the behavior at approximately:
        *   1200px width
        *   992px width
        *   768px width
        *   576px width
    4.  **Simulate Tablet View:**  Use browser developer tools (e.g., Chrome DevTools Device Toolbar) to simulate a tablet device (e.g., iPad, iPad Pro) in both portrait and landscape orientations.  Observe the layout and content arrangement. Verify that all elements are visible and usable.
    5.  **Simulate Mobile View:** Use browser developer tools to simulate a mobile device (e.g., iPhone, Android phone) in both portrait and landscape orientations. Observe the layout and content arrangement. Verify that all elements are visible and usable, especially menus, buttons, and form elements.
    6.  **Content Overflow:** Check for horizontal scrolling or content overflow at each screen size.
    7.  **Image Scaling:** Verify that images scale appropriately without distortion or loss of quality at all screen sizes.
    8.  **Text Readability:** Ensure that text is readable and doesn't overlap or become too small at any screen size.
    9.  **Menu Functionality:** On smaller screens, verify that the navigation menu collapses into a hamburger menu or similar.  Confirm that the menu is easily accessible and functional.
    10. **Form Element Rendering:** Verify the rendering of form elements (input fields, text areas, checkboxes, radio buttons, dropdowns) across all screen sizes.  Ensure they are properly sized and aligned.
*   **Expected Result:**

    *   The website layout should adapt fluidly to each screen size, maintaining a visually appealing and usable experience.
    *   Content should reflow appropriately to avoid horizontal scrolling or content overflow.
    *   Images should scale without distortion or loss of quality.
    *   Text should remain readable at all screen sizes.
    *   Navigation menus should collapse into a smaller format (e.g., hamburger menu) on smaller screens and function correctly.
    *   Form elements should render correctly and be usable at all screen sizes.
    *   There should be no broken or misaligned elements across different screen sizes and orientations.
*   **Priority:** High (Essential for usability and accessibility)

**Test Case 2:  JavaScript Functionality - Form Validation**

*   **Title:** Form Validation Functionality
*   **Description:** This test case verifies that JavaScript-based form validation is working correctly on a specific form on the website. It covers various validation scenarios, including required fields, data type validation, and format validation.
*   **Steps:**

    1.  **Setup:** Navigate to the specific form page on the website (e.g., registration form, contact form).
    2.  **Empty Submission:** Submit the form without entering any data in any field.
    3.  **Required Field Validation:** Verify that error messages are displayed for all required fields, indicating that they cannot be left blank.
    4.  **Incorrect Data Type (Email):** Enter an invalid email address (e.g., "test", "test@test") into the email field. Submit the form.
    5.  **Email Format Validation:** Verify that an error message is displayed indicating that the email address is not in a valid format.
    6.  **Incorrect Data Type (Number):** If there's a number field, enter non-numeric characters (e.g., letters, symbols). Submit the form.
    7.  **Number Format Validation:** Verify that an error message is displayed if non-numeric characters are entered in a numeric field.
    8.  **Password Confirmation:** If the form includes a password and password confirmation field, enter different values in the two fields.  Submit the form.
    9.  **Password Mismatch Validation:** Verify that an error message is displayed indicating that the passwords do not match.
    10. **Minimum/Maximum Length:** If any fields have minimum or maximum length requirements, enter values that are too short and too long. Submit the form.
    11. **Length Validation:** Verify that error messages are displayed for values that violate the minimum or maximum length restrictions.
    12. **Special Character Validation:** If any fields have restrictions on special characters, try entering restricted characters. Submit the form.
    13. **Character Restriction Validation:** Verify that an error message is displayed if a user enters an invalid character.
    14. **Valid Submission:** Enter valid data in all required fields, adhering to all validation rules. Submit the form.
    15. **Successful Submission:** Verify that the form submits successfully and the user receives a confirmation message or is redirected to the appropriate page.
*   **Expected Result:**

    *   Error messages should be displayed for all validation failures, clearly indicating the nature of the error to the user.
    *   Validation rules should be enforced correctly (e.g., required fields are checked, email addresses are in the correct format, passwords match, length restrictions are enforced).
    *   The form should not submit successfully if there are any validation errors.
    *   Upon successful submission with valid data, the user should receive a confirmation message or be redirected to the appropriate page.
*   **Priority:** High (Critical for data integrity and user experience)

These test cases are designed to be comprehensive and cover common scenarios. Remember to adapt them based on the specific features and requirements of the "Frontend" you are testing. Good luck!
